# Quiet Zeros

**Quiet, private calculators.** A free, ad-supported static site of financial and everyday
calculators plus downloadable Excel templates. Every calculation runs client-side — nothing a
visitor types ever leaves their browser, and the Content-Security-Policy makes that enforceable,
not just a promise.

- Zero dependencies, zero build step, zero servers. Plain HTML/CSS/ES modules.
- Self-hosted fonts (Fraunces + Inter, both SIL OFL). No third-party requests of any kind.
- Costs $0/month to run on any static host's free tier.

## Deploying (free hosting + free TLS certificate)

Both options below serve over HTTPS with an automatically provisioned, auto-renewing
certificate (Let's Encrypt / Google Trust Services) at no cost.

### Option A — Cloudflare Pages (recommended)
1. Push this folder to a GitHub repository.
2. In the Cloudflare dashboard: **Workers & Pages → Create → Pages → Connect to Git**, pick the
   repo, leave the build command empty, output directory `/`.
3. You get `https://<project>.pages.dev` immediately with TLS. The `_headers` file is applied
   automatically (full security headers, HSTS, immutable font caching).
4. When you buy `quietzeros.com` (verified available Sep 2026), add it under **Custom domains** —
   the certificate is issued automatically.

### Option B — Azure Static Web Apps (free tier)
1. Push this folder to a GitHub repository.
2. Azure Portal → **Create a resource → Static Web App** → plan **Free** → connect the GitHub
   repo. Build presets: **Custom**; app location `/`; leave api/output blank. Azure adds a
   GitHub Actions workflow and deploys on every push.
3. You get `https://<name>.azurestaticapps.net` with a free managed TLS certificate.
   Custom domains (e.g. `quietzeros.com`) also get free managed certificates: **Settings →
   Custom domains → Add**.
4. Azure ignores `_headers`; the included `staticwebapp.config.json` applies the same
   security headers, caching rules, and the 404 page. Free tier: 100 GB bandwidth/month,
   2 custom domains — plenty for this site.

### Option C — GitHub Pages
1. Push to GitHub → repo **Settings → Pages → Deploy from branch**.
2. Served at `https://<user>.github.io/<repo>/` with free TLS.
3. GitHub Pages ignores `_headers`; the per-page `<meta http-equiv="Content-Security-Policy">`
   still applies, but HSTS/X-Frame-Options do not. Prefer Cloudflare Pages if possible.

```
assets/js/data/offers.js   Bank/card offers (refresh monthly; affiliate URL slots)
assets/css/main.css        The entire design system (tokens, light/dark, charts, forms)
assets/js/core.js          Helpers: safe DOM builder, formatters, validation, amortization math
assets/js/charts.js        Hand-rolled SVG charts (stacked area, breakdown bar, tables)

assets/js/tools/<slug>.js  One module per calculator
downloads/*.xlsx           Excel templates (generated by scripts/build_excel.py)
scripts/gen_pages.py       Tool-page generator (shared shell + per-tool content)
scripts/build_excel.py     Excel template builder (openpyxl)

```

## Adding a new calculator

1. Add an entry to `TOOLS` in `assets/js/registry.js` (slug, name, description, category).
2. Add a dict to `TOOLS` in `scripts/gen_pages.py` (form fields, results layout, methodology
   prose) and run `python scripts/gen_pages.py`.
3. Create `assets/js/tools/<slug>.js` — read inputs with `readField()`, write results with
   `textContent`, draw charts with `stackedArea`/`breakdown`, and wire it with `bindCalc()`.
4. Add the URL to `sitemap.xml`. If it has an Excel twin, add a builder to
   `scripts/build_excel.py` and a card to `downloads.html`.

House rules for new code (these are the security model — keep them):
- **Never** assign `innerHTML`/`outerHTML` or use `eval`/`Function`. Build DOM with `el()`/`svgEl()`;
  all text lands via `textContent`.
- Every input goes through `readField()` (coerce → clamp → flag), never raw `.value` into math.
- No external scripts, styles, fonts, or images. The CSP will block them anyway — that's the point.
- No new storage. The only persisted byte is the theme preference.

## Turning on real ads (the revenue switch)

The site ships with labeled, fixed-size placeholder ad slots (`<aside class="ad-slot">`) — one
per page, below the results, never inside a calculator. To monetize:

1. **Get approved.** Apply to Google AdSense once the site is on its own domain with some
   traffic. The per-tool "How this is calculated" sections exist partly to pass AdSense's
   low-value-content review. (Finance calculators with US traffic typically earn ~$8–25 RPM —
   far more than privacy-focused networks; EthicalAds is the alternative if you'd rather keep
   the no-tracking promise absolute, at meaningfully lower revenue.)
2. **Consent.** Enable Google's certified consent message (AdSense → Privacy & messaging).
   It is mandatory for EEA/UK/Switzerland visitors.
3. **Loosen the CSP** — currently it blocks all third parties by design. In `_headers` and in
   each page's `<meta>` CSP, extend:
   `script-src 'self' https://pagead2.googlesyndication.com https://fundingchoicesmessages.google.com;`
   `frame-src https://googleads.g.doubleclick.net https://tpc.googlesyndication.com;`
   `img-src 'self' data: https:; connect-src https://pagead2.googlesyndication.com;`
4. **Paste the ad unit** inside the `.ad-slot` aside (replace the placeholder spans, keep the
   "Advertisement" label — it's an FTC expectation and a trust feature).
5. **Update `privacy.html`** — the Advertising section already anticipates this; disclose the
   ad cookies and link Google's partner policy.

Keep it to 1–2 units per page. Restraint is also the revenue-optimal strategy: more ads lower
both UX and per-ad viewability.

## Affiliate revenue (best-accounts.html)

The accounts & cards page renders from `assets/js/data/offers.js`. Each entry has an
`aff: null` field — once you enroll in affiliate programs (Impact, CJ, Sovrn Commerce,
FlexOffers, or issuers' own programs), paste your tracking URL there; the page automatically
switches that entry's link and marks it `rel="sponsored"`. House rules, already encoded in
the page copy: disclosure sits above the lists (FTC "clear and conspicuous"), ranking is by
the published numbers only, and every table shows its compilation date.

**Data refresh cadence** (data integrity first):
- `offers.js` — monthly: re-verify each APY/offer on the institution's own page, bump `asOf`.
- `assets/js/data/tax-2026.js` — yearly: rebuild from the new IRS revenue procedure +
  retirement-limits notice + Tax Foundation state table when they land each fall. There is no
  free tax-rules API; commercial engines (Symmetry, Avalara) are the paid alternative, and
  NBER TAXSIM would send user income to a third party — an annual data refresh preserves the
  privacy promise at $0.

## Deploying updates

Always deploy through the staging script — it stamps every asset URL and module
import with the git sha, which is what prevents browsers from pairing cached old
JavaScript with fresh HTML (Cloudflare Pages caches assets for 4 hours and its
_headers file cannot lower that):

```
git add -A && git commit -m "..." && git push
python scripts/stage_deploy.py /tmp/deploy
npx wrangler pages deploy /tmp/deploy --project-name quietzeros --branch main --commit-dirty=true
```
